# Cloudflare 配额方案复核

## 结论与范围

先修复可复现的重复请求，不直接照搬原来的 12 项计划。本次只改本地代码和测试，没有部署、操作远端 D1、创建付费资源或修改 WAF。

2026-11-09 复核时的基线为 `b96c1e2`。工作区原有的鉴权、身份头净化、角色检查和注册接口删除属于另一批未提交改动；本次保留，不代为提交。

没有线上请求分布、D1 `rows_read` 或错误日志，不能确认哪种配额先耗尽，也不能承诺“减少 80%”。D1 按扫描行数计量，不是按 SQL 条数计量；ORM 的关联查询也不能按每张表算一次独立请求。

## 原计划逐项调整

| 原任务 | 处理 |
|---|---|
| T1 robots.txt | 基线已有 `Disallow: /`，保留。它只约束守规则的爬虫，不是限流或鉴权。 |
| T2 后台暂停 | 基线已有事件监听，但初始隐藏、请求重叠、失效后切回标签页会恢复等边界不完整。本次统一轮询调度，串行请求、隐藏暂停、卸载取消，401/403/404/410 停止自动轮询。 |
| T3 30 秒轮询 | 基线已是 30 秒，不重复修改。临时失败采用 60、120、240、300 秒的退避，成功后恢复 30 秒。 |
| T4 删除 count | 不采纳直接删除。`total` 被现有界面和 API 消费；分享列表也有计数查询。先减少请求，再根据实际扫描量决定是否增加兼容的按需计数参数，不伪造总数。 |
| T5 角色放 JWT | 不采纳长期角色快照，否则降权不能及时生效。当前未提交的中间件已复用一次身份解析，并将可信用户 ID 传入路由；保留实时角色查询。 |
| T6 收件 Worker | 已修：先匹配未过期收件人，再解析 MIME（邮件原始格式）；不存在或过期则拒收，不写库、不发 webhook。去掉正常处理日志中的正文、主题和收件地址；无归属用户的邮箱不查 webhook。 |
| T7 DELETE LIMIT | 本地 D1 实测原 SQL 可运行，批量 100 个邮箱、关联删除、重复执行都通过。没有语法错误证据，保留原 SQL，不做猜测性修复。 |
| T8 KV 限流 | 不采纳逐请求读改写 KV。免费写入额度低、同键限速、非原子更新，容易先把 KV 用完。应优先评估函数执行之前的边缘拦截；线上规则、阈值和域名覆盖仍需单独批准与验证。 |
| T9 X-User-Id | 原有未提交改动已净化后通过 `NextResponse.next({request:{headers}})` 传递。当前工作区无会话伪造该头访问 `/api/emails` 实测 401；未把它当成完整鉴权审计。 |
| T10 角色查询权限 | 原有未提交中间件已为 `/api/roles/users` 加入 `PROMOTE_USER` 检查。完整管理员/普通用户/API Key 权限矩阵仍需独立验收。 |
| T11 删除注册接口 | 已在用户暂存区，保持原样。登录表单中的注册调用和入口原本已注释，不另做无关清理。 |
| T12 语言配置 | 按当前布局固定中文的实际行为，只启用 `zh-CN`；中文变体回退到简体。保留现有英文翻译文件，不恢复多语言产品范围。 |

### 原计划漏掉的两处请求放大

- `use-config.ts` 原来在 `loading` 从 true 变回 false 时再次发起请求，401/503 或异常响应会无间隔重试。浏览器用模拟 503 复现到夹具的 10 次保护上限；修复后只有 1 次。多个组件同时读取配置也合并为一次请求。
- `ThreeColumnLayout` 原来同时挂载桌面和移动列表，CSS 隐藏不会停止组件的副作用。本次只挂载当前断点对应的布局。浏览器在桌面和手机宽度下选邮箱都只发起 1 次消息列表请求。

## 验证与复现

```sh
WRANGLER_SEND_METRICS=false pnpm test:quota
pnpm exec tsc --noEmit --incremental false
NEXT_TELEMETRY_DISABLED=1 pnpm lint
NEXT_TELEMETRY_DISABLED=1 pnpm build
```

- 15 项自动测试：定时器、初始隐藏、串行请求、手动刷新并发、终止状态、退避、分页参数、卸载取消、网络失败、语言资源，以及本地 D1 的收件/清理行为。
- D1 用实际 Wrangler 本地运行时和全部仓库迁移，数据库是临时、非持久的；不用真实邮箱或外部 webhook。
- Chrome 浏览器回归：1281 和 390 像素宽度，通过隐藏/恢复、403 停止、切换邮箱、分享 410 停止及配置 503 不循环的测试。接口响应和可见性事件由夹具控制，不等同于真实登录、SMTP 投递或线上容量验收。复现见 [浏览器回归说明](../tests/browser/README.md)。
- 类型检查、lint、Next.js 生产构建通过。保留 4 条既有 Hook 依赖 warning；构建仍有旧 Browserslist 数据及 next-on-pages 的 Edge Runtime warning，未升级依赖或锁文件。
- 收件和清理 Worker 均通过 `wrangler deploy --dry-run` 打包；没有真正上传。未验证 Pages 适配器的完整发布产物。

## 发布前还缺什么

1. 明确纳入并验证另一批鉴权改动，不要仅凭本次配额提交就认定所有安全任务已完成。
2. 由线上指标确认 Functions 请求数、D1 扫描/写入行数、KV 读写及其 UTC 时间段；比较部署前后相同长度的流量窗口。
3. 确认实际运行版本、清理日志和积压。当前清理上限仍是每次 100 个邮箱；关联邮件及索引写入不包含在这 100 个邮箱的数量内。
4. 大邮件体积上限、失败重投以及边缘限流不在本次已验证范围；不能声称此补丁已解决全部配额或投递可靠性问题。

## 官方依据

- [Pages Functions 配额](https://developers.cloudflare.com/pages/functions/pricing/)：与 Workers Free 共享每天 100,000 次请求，未执行函数的静态资源不计入该额度。
- [D1 计量](https://developers.cloudflare.com/d1/platform/pricing/)：免费每天 5,000,000 行读取、100,000 行写入；扫描量应读取实际指标。
- [KV 限制](https://developers.cloudflare.com/kv/platform/limits/)：免费每天 1,000 次写入，同一键每秒最多 1 次写入。
- [KV 一致性](https://developers.cloudflare.com/kv/concepts/how-kv-works/)：不适合需要原子读改写的计数器。
